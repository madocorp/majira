# MaJira

MaJira is a tile based Jira Cloud browser built with the current SPTK. Start it with `php majira.php` in a graphical session.

On first use, open **Settings** (F5), enter the Jira site URL, email and API token, then save and test the connection. The saved token is not shown on the screen when the app opens; leave its field blank to keep it. Project choices load automatically after connecting. On **Filters** (F2), select a project or choose **Any project**, and, if needed, a board and sprint. Confirming a project with Return or Esc loads its boards and its status, type, available priority, and assignee choices, even with no board selected. **Any project** uses global statuses, visible issue types, site priorities, and users returned by Jira's user search; that user search requires Browse users and groups permission and is limited to the first 1,000 users. Confirming a board with Return or Esc loads its sprints. Moving through project, board, and sprint lists does not fetch data. Their choices are cached separately by project or board, including empty results. **Clear cache** on Filters discards these choice caches and reloads projects; confirm a project or board to fetch its choices again. Cached tickets remain available. Project and sprint become JQL clauses. Board selection narrows the available sprint choices; **No board selected** adds no condition to ticket searches. The choice lists, ticket search, ticket details and filter options are cached in SPTK's private application data directory. Cached tickets are restored at startup. On **List** (F1), F5 refreshes the first page. When more results are available, the status bar shows the loaded count and M (or F6) loads the next page.

The **Filters** screen shows saved filters on the left, a deck of filter cards in the middle, and actions on the right. The first card contains the filter name. **New filter** creates a blank builder filter named `new` and activates its name input; editing the name saves or renames it. Duplicate names are rejected. The saved list does not search as you type; Shift+Up/Down reorders its entries and saves their order. Moving through the saved list loads each filter and opens its name card in builder mode. Up and Down move between builder cards; the selected card expands while the others show their current values in two lines. Right from saved filters or Left from the action column selects the open card. Open a list with Return, make a selection, and press Esc to keep it. Created and Updated have independent From and To slots. Both are empty by default: focus a slot and press Return to add and activate a calendar, or press Delete on a calendar to remove it. Either date may be used alone; To includes the whole selected day. Builder changes save immediately, and **Apply** runs the current filter. **Clear filter** resets the current filter's values and query while keeping its name and mode; other saved filters are unchanged. **Delete filter** loads the next saved filter, or the previous one when the last row is deleted. The action shortcuts are N (new), J (JQL), A (apply), D (delete), C (clear filter), and R (clear cache). **Switch to JQL** generates a query from the builder values and replaces the builder cards with the name input and an editable JQL field. JQL edits save immediately. This choice is permanent for that filter; create a new filter to use the builder again. The List sidebar starts with **Last JQL**, followed by saved filters. It highlights the active saved filter, or **Last JQL** after a direct edit. Return applies the highlighted item and activates the table when the search returns tickets; Esc closes the sidebar and restores the previous tile focus. Empty results leave the current tile focused. **Last JQL** restores the most recent direct edit after switching to a saved filter. Press F to open the sidebar, including while the ticket table is active. Alternatively, edit raw JQL on **List**; it runs when editing ends and activates the table if tickets are found. The **Ticket** screen (F4) shows details, allows summary and description edits and new comments, and provides **Open key** and **New ticket** actions. Jira requests appear in the status bar before they run.

The **Board** screen (F3) is an empty placeholder for a later active sprint view. The current pass does not yet include the old app's workflow transitions, attachment download, field chooser, comment editing, or complete filter menu. Jira requests run synchronously after their status message is drawn.

PHP extensions required by SPTK and the Jira client include FFI, SDL dependencies, XMLReader, mbstring, curl and pcntl. The application stores settings and Jira caches through `SPTK\Core\AppData`; keep that private directory out of version control.

Run `php Tests/JiraData.php` for the cache and paging check, `php Tests/ListLayout.php` for the List sidebar layout check, `php Tests/FiltersLayout.php` for the filter tile layout check, `php Tests/SavedFilters.php` for saved filter modes, and `php Tests/DateFilters.php` for date filter queries.
